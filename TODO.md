## Implementation and project structure

The production stack uses React/TypeScript, HTML/CSS, Express/Node.js and managed MySQL through Drizzle. React is hydrated from complete build-generated page HTML. Express serves the site and server-validated private inquiry endpoint. The WhatsApp webhook scaffold remains disabled until official Meta credentials are provided.

`client/src/components` contains shared layout/brand, WhatsApp contact and service-request components. `client/src/pages` contains homepage, courses, services, resources, about/legal, contact and review routes. `client/src/data` contains course/service/article catalogues, site metadata and WhatsApp/review message builders. `client/public` contains route and favicon manifests plus supplied service images. `server/leadRoutes.ts` implements inquiry capture; `server/whatsappBot.ts` and `server/whatsappRoutes.ts` implement the inactive Cloud API scaffold. `drizzle/schema.ts` and migrations describe persistence; the bot-event migration is not applied. `scripts/prerender.tsx` emits the public page HTML at build time. No database credentials are embedded in the browser or prerender output.
